android/ — topology
====================

This is a SEPARATE, self-contained Gradle build from ../java/ (which has
its own gradlew and its own settings.gradle.kts). The two are linked by
a Gradle *composite build*: settings.gradle.kts here does

    includeBuild("../java")

which pulls java/'s subprojects (libdraw, libexpr, libflow) in as if they
were local modules, without publishing jars anywhere. app/build.gradle.kts
then just says implementation("org.rapidcow.trivnote:libexpr") etc. and
Gradle substitutes in the real ../java/libexpr project at build time
(this only works because each java/*/build.gradle.kts declares
group = "org.rapidcow.trivnote" — that's the coordinate Gradle matches on).

Proxy note (relevant if building from a machine that needs one)
-----------------------------------------------------------------
Gradle does NOT read the HTTP_PROXY / HTTPS_PROXY environment variables —
it only honors JVM system properties. The systemProp.* lines you found in

    ~/.gradle/gradle.properties        (note: ~/.gradle, i.e. the Gradle
                                         USER home directory — NOT this
                                         project's own ./gradle.properties)

are exactly that mechanism:

    systemProp.http.proxyHost=127.0.0.1
    systemProp.http.proxyPort=7890
    systemProp.https.proxyHost=127.0.0.1
    systemProp.https.proxyPort=7890

Because it lives in the Gradle *user* home (~/.gradle/gradle.properties),
not in this repo's ./gradle.properties, it applies to every Gradle project
you build on that machine and never gets committed/shared — which is the
right place for it: a proxy setting is a fact about your network, not
about this project, so it shouldn't end up in git and forced onto every
other machine (like this one) that doesn't need it.

If a proxy ever needs credentials, the equivalent keys are
systemProp.http.proxyUser / systemProp.http.proxyPassword (and https.*
variants), and systemProp.http.nonProxyHosts=host1|host2 to exclude hosts.
